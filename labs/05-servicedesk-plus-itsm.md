# Lab 05 — ManageEngine ServiceDesk Plus and ITSM

## Objective
Install a safe lab instance and practise the complete ticket lifecycle: receive, classify, prioritise, assign, diagnose, communicate, resolve, confirm and close.

## Core concepts

| Concept | Meaning |
|---|---|
| Incident | Unplanned interruption or reduction in service quality |
| Service request | Standard request for access, software or information |
| Problem | Underlying cause of one or more incidents |
| Change | Controlled addition, modification or removal that may affect services |
| SLA | Agreed response and resolution target |
| Knowledge article | Reusable solution for technicians and self-service |
| Asset/CMDB | Tracked technology items and their relationships |

## Safe installation outline

1. Build a supported isolated VM and take a snapshot.
2. Download the official evaluation installer.
3. Install using the approved database option.
4. Start the service and open the web console on the configured port.
5. Replace default credentials immediately and restrict network access.
6. Configure time zone, business hours, roles, mail, categories, SLAs and technicians.
7. Back up the application and database before major changes.

## Ticket exercise

Process the request **“Laptop does not power on.”**

1. Record user, device, asset and contact details.
2. Categorise as `Hardware > Laptop`.
3. Determine impact and urgency using business effect.
4. Assign the correct support group and start SLA tracking.
5. Add factual work notes for each diagnostic action.
6. Record the resolution, verification, user confirmation and closure code.
7. Create or link a knowledge article when reusable.

## Reports to review

- Open incidents by priority and age
- SLA breaches and near breaches
- First response time and mean time to resolve
- Reopened tickets
- Backlog by category and technician
- Customer satisfaction
- Recurrent incidents and problem candidates

## Interview answers

**How do you prioritise an incident?**

> I calculate priority from impact and urgency. Impact measures the business scope; urgency measures how quickly restoration is required. I follow the approved matrix and document the reason.

**What makes a good update?**

> A good update is time-stamped, factual and concise. It records the action, evidence, current status, user communication, next step and owner rather than simply saying “fixed”.
