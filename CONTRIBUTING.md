# Contributing

Thank you for helping improve this hands-on lab portfolio.

## Contribution workflow

1. Fork the repository and create a focused branch.
2. Keep examples safe for isolated lab environments.
3. Use clear Markdown headings, fenced code blocks and verification steps.
4. Include troubleshooting, security and rollback considerations where relevant.
5. Remove passwords, tokens, tenant names, customer data, public IP addresses and other sensitive information.
6. Open a pull request describing the problem, the change and how it was verified.

## Lab format

Each lab should contain:

- Objective
- Why it matters
- Prerequisites
- Procedure
- Verification
- Troubleshooting
- Security considerations
- Interview-ready explanation

## Style

Use concise professional English. Commands must be copyable, but readers must still validate product versions and official documentation.
